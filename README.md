# Solver piecewise linear route

Интерактивное десктоп-приложение на **C++17 + SFML 2.5** для визуального
поиска оптимального ломаного маршрута по дискретному полю (карте рельефа).

Пользователь задаёт стартовую и конечную точки (а при желании — промежуточные
повороты) и ограничение на угол поворота, а программа строит маршрут,
минимизирующий дискретную «трудность пути» (сумму значений поля вдоль ломаной).
В приложении реализованы несколько методов поиска: полный перебор по сетке,
перебор с ограничением области, метод ограниченных прямоугольников, метод
углов и динамическое программирование.

## Постановка задачи

Даны две точки на плоскости, допустимое число промежуточных поворотов n
и ограничение на модуль угла поворота phi_0. Требуется построить ломаную
из (n + 1) звеньев, соединяющую заданные точки, которая минимизирует
«трудность пути» — сумму значений поля (рельефа) вдоль каждого звена.
Поле задано на сетке: это карта, загружаемая из изображения, либо
синтетическая функция`myFunction()`.

Точки излома ломаной называются **поворотами**, отрезки между ними —
**звеньями**, на каждом звене разрешён поворот не более чем на phi_0
градусов. В коде «уровнем» называется строка сетки (координата y) внутри
текущей области-ограничителя, которую перебирает алгоритм полного
перебора; именно «оставшиеся уровни» показываются в счётчике прогресса.

## Возможности

- Интерактивное редактирование рельефа: ЛКМ — поднять, ПКМ — опустить.
- Генерация поля аналитической функцией `myFunction()`.
- Загрузка поля из изображения (градации серого).
- Добавление/удаление промежуточных поворотов, перетаскивание маркеров.
- Два ограничителя: максимальная разница соседних клеток `maxDifference`
  и максимальный угол поворота `phi_0` (слайдеры).
- Расчёт маршрута методами (к кнопкам подключены два):
  - **DP Method** — динамическое программирование по сетке;
  - **Full Walk Method** — метод 3: полный перебор с ограничениями.
    Область допустимых продолжений пути строится по точной формуле
    множества допустимых ломаных при ограничении на угол поворота.
  - остальные методы не подключены к кнопкам, но сохранены в коде:
    полный обход поля (`calculateOptimalSolutionWithFullFieldWalk`),
    метод ограниченных прямоугольников (`…ByApproxWithRect`,
    `…Experiment`), метод углов (`…ByAngle`),
    серия экспериментов (`makeExperiment`).
- Печать текущего пути и его стоимости в консоль (кнопка **Print way**).

## Требования

| Зависимость | Версия | Назначение |
|---|---|---|
| C++ компилятор (MinGW-w64 / MSVC / Clang) | C++17 | сборка проекта |
| CMake | >= 3.10 | сборка проекта |
| SFML | 2.5.x | графический интерфейс (Graphics, Window, System) |
| Шрифты (в `resources/`) | Arial, Consola | `arial.ttf`, `consola.ttf` рядом с exe |

SFML 2.5 нужно установить заранее. Способы:

- **Windows:** бинарная сборка с [sfml-dev.org](https://www.sfml-dev.org/download/sfml/2.5.1/)
  под ваш компилятор (например, `SFML-2.5.1-windows-gcc-7.3.0-mingw-64-bit.zip`),
  или сборка из исходников. Обязательно выбирайте версию, собранную **тем же
  компилятором/ABI**, что и ваш проект (иначе при запуске будет
  `0xC0000139` / `STATUS_ENTRYPOINT_NOT_FOUND`).
- **Linux:** `sudo apt install libsfml-dev` (или `brew install sfml`).
- **macOS:** `brew install sfml`.

При использовании **статической** сборки SFML добавьте
`-DSFML_STATIC_LIBRARIES=TRUE`; при **динамической (DLL)** — рядом с
исполняемым файлом должны лежать `sfml-graphics-2.dll`, `sfml-window-2.dll`,
`sfml-system-2.dll` (и `openal32.dll` при использовании Audio).

## Сборка

### 1. Установите зависимости

- **SFML 2.5** (см. раздел «Требования»): скачайте/соберите версию под ваш
  компилятор и распакуйте. Запишите путь до папки с `include/` и `lib/`
  (для Windows) или путь к `SFMLConfig.cmake`.
- **Компилятор**: MinGW-w64 (например, через WinLibs), MSVC или Clang.
- **CMake** >= 3.10.

### 2. Настройте и соберите

```bash
# Linux / macOS (SFML из apt/brew)
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j

# Windows + MinGW (статическая сборка SFML: -DSFML_STATIC_LIBRARIES=TRUE)
cmake -S . -B build -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release \
      -DSFML_DIR=/path/to/SFML/lib/cmake/SFML -DSFML_STATIC_LIBRARIES=TRUE
cmake --build build -j

# Windows + Visual Studio
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
```

> Если SFML установлен в нестандартном месте, передайте
> `-DSFML_DIR=/путь/к/SFML/lib/cmake/SFML` (Windows) или
> `-DSFML_ROOT=/путь/к/SFML` (Linux/macOS).
>
> Проект собран с SFML 2.5. В **SFML 3** API изменился
> (например, `sf::Text::getLocalBounds`, сигнатуры `loadFromFile`).
> Без адаптации кода сборка с SFML 3 не сработает.

### 3. Запустите

После сборки исполняемый файл будет в `build/` (или `build/Release/` на Windows
с генератором Visual Studio). CMake автоматически скопирует шрифты из
`resources/` рядом с exe — отдельно их класть не нужно, если сборка через CMake.

```bash
./build/solver
# или Windows (MinGW Makefiles)
.\build\solver.exe
# или Windows (Visual Studio)
.\build\Release\solver.exe
```

При **динамической** сборке SFML убедитесь, что DLL SFML лежат рядом с exe
(или в PATH).

## Использование

1. Запустите приложение — откроется окно с полем.
2. Перетащите красный (**Start**) и синий (**End**) маркеры.
3. Настройте угол и максимальную разницу (слайдеры).
4. При необходимости добавьте повороты (**Add turns**) или измените рельеф.
5. Нажмите **DP Method** или **Full Walk Method**, чтобы найти маршрут.
6. **Print way** выводит координаты и стоимость пути в консоль.

## Управление мышью

| Действие | Результат |
|---|---|
| ЛКМ по клетке (режим «Change grid») | поднять рельеф |
| ПКМ по клетке (режим «Change grid») | опустить рельеф |
| ЛКМ по маркеру | перетаскивание/выбор поворота |
| Кнопки | генерация/загрузка поля, поиск, печать |

## Замечания и ограничения

- Проект рассчитан на **SFML 2.5** — переход на SFML 3 потребует
  адаптации кода (см. предупреждение в разделе «Сборка»).
- Ресурсы (`arial.ttf`, `consola.ttf`) лежат в `resources/`; при сборке через
  CMake они копируются рядом с исполняемым файлом автоматически.
- Иконка окна: программа при запуске пытается загрузить `mai.png`
  (`app.h` → `App::init()`).
- Алгоритмы поиска выполнены в виде отдельных методов класса `App`.
  К интерфейсу подключены **DP Method** и **Full Walk Method**;
  остальные методы (полный обход поля, прямоугольники, углы, эксперимент)
  сохранены в коде, но отключены.
